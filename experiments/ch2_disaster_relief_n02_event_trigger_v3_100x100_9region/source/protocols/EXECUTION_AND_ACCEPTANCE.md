# N02 v3 execution and acceptance

The user specification is authoritative. V2 is frozen historical C0. This project begins from the exact manifest entries recorded in BASELINE_PROVENANCE.json, without old requests, authorizations, attempts, outputs, ledgers or model weights.

Luna implements and executes. Sol 6.1 High reviews immutable bytes and raw evidence in a separate context; it does not edit reviewed implementation. This is an independent-context control within the same model family, not external certification. Coordinator records node outcomes and gates subsequent runs.

S0 records the first failed link in the original six-platform/twelve-task chain. A failure stops that attempt. A repaired diagnostic fixture receives a new identity, discloses all timeline changes, and obtains its initial queues from public C1, never hand-entered queues. A new diagnostic success cannot retroactively change the historical failure.

S1 requires executed evidence at 30 platforms and 45 total tasks: public C1 input/output, scope dictionaries, complete candidate catalogs, requested/repaired/executed actions, before/after owner and queue states, raw branch trajectories and communication records. Eight event classes are separately covered. Local-alternative count applies to repairable mechanism witnesses. Physically impossible events instead need an explicit rejection/fallback reason; dummy candidates are forbidden.

Coordinates use the half-open domain [0,100). Region neighborhoods include diagonals, as in the user's r00 example. Helicopters have null region ownership and null region_center; their spatial position is still the specified non-diagonal center. Operational connectivity and resource/critical-platform criteria must be recorded from the frozen implementation before acceptance.

The 2x2 witness pairs patch-on and patch-off runs with otherwise identical initial state, actions, event tape and random inputs. It records a traversing and a nontraversing path, physical integrals, and task outcomes. NOOP and non-target labels are independently recomputed from raw events/states by the reviewer. Producer labels and a producer-internal oracle alone cannot certify independent recomputation.

Before S2 launch, A/B/C reviews must pass and all source, scenario, threshold, reward, training and acceptance configuration bytes are frozen. GPU training uses a fresh identity and native Windows OpenSSH upload/execute/fetch. Existing pinned runtime is verified with a seeded CUDA forward/backward witness. There is no CPU training fallback and no unrelated process termination.

S2 uses seed 8201, four train and two development parents, one training round, no world model, and at most 32 real PPO updates per variant. Periodic-G and Event-G share initialized actors and the same parent/tape/split identities. Calibrations use training observations only. Development is evaluated without tuning. The exact tolerance explicitly chosen by the user is Event-G minus Periodic-G utility >= 0 and on-time >= -0.02. All actions must be legal; actual local repair must not systematically vanish; at least one audited local witness and one strictly reduced eligible mean development cost are required. Cost candidates are planning calls, communication messages and reconstruction size. A pilot is not a significance claim.

S3 is conditional on S2 independent PASS. It cannot be authorized by a synthetic gradient probe or merely successful GPU execution. World-model and PPO updates, fresh-process restoration, auxiliary updates, frozen world-model tensors, actor isolation and resource settlement require direct evidence.

Every formal attempt has new request/attempt/authorization/ledger identities and hash-bound source/config/data. A manifest lists bytes before execution; raw evidence is frozen separately after execution to avoid circular hashes. Failure evidence is retained. Public archive excludes secrets, private connection context, unsanitized authorizations and personal paths. Tags state the actual result; no acceptance is inferred from a successful upload.
