# 第二章可执行研究方案 V1

## 题目与研究主线

**题目：动态扰动下异构无人机集群任务分配的事件触发式实时重构方法**

第一章输出初始任务分配。第二章持续接收无人机、任务、环境和通信状态，并执行：

```text
动态扰动检测
→ 事件触发判定
→ 受影响任务与无人机识别
→ 局部/全局重构选择
→ 候选任务分配生成
→ 世界模型预测候选后果
→ 分层强化学习选择方案
→ 能力、时间、能量、通信约束修复
→ 输出新的任务分配
→ 交给第三章进行编队和安全航迹规划
```

现有已经通过验收的 N02 100×100 实现作为代码基线，新实验建立独立版本：

```text
development/ch2_disaster_relief_n02_event_trigger_v1_100x100/
```

地图固定为 `100×100`，扩大任务、平台和事件数量，不改变地图合同。

## 一、系统状态与图结构

系统状态表示为异构图：

```text
无人机节点：
位置、剩余能量、载荷、健康状态、任务能力、通信质量

任务节点：
位置、优先级、剩余工作量、截止时间、完成进度、前置关系

环境节点：
风场、障碍、威胁区域、可通行性、风险等级

通信边：
链路质量、延迟、丢包率、连通状态

分配边：
无人机—任务当前分配关系、任务切换代价、协同关系
```

图节点和边必须只使用当前公共观测。未来事件、隐藏任务状态和真实分支结果只能用于离线标签审计，不能进入策略输入。

第一轮实验固定为：

- 地图：100×100；
- 父场景：6个；
- 训练场景：4个；
- 开发场景：2个；
- 平台：4 UAV + 2 helicopter；
- 任务：每场景12个；
- 随机种子：8201、8202、8203；
- 空间扰动：2×2；
- 决策窗口：8、16、24、32分钟。

训练场景覆盖：

1. 新任务到达；
2. 无人机故障；
3. 能量快速下降；
4. 通信质量下降。

开发场景覆盖：

5. 环境或威胁区域变化；
6. 多种扰动同时发生。

## 二、动态扰动检测

每个时间步比较当前状态与上一状态，形成四类扰动量：

```text
任务扰动：
新任务、任务取消、优先级变化、截止时间变化

平台扰动：
故障、能量下降、能力失效、载荷变化

环境扰动：
风场变化、障碍变化、威胁区域变化、可通行性变化

通信扰动：
链路质量下降、节点失联、网络连通分裂
```

每个扰动计算标准化严重度：

```text
d_task
d_platform
d_environment
d_communication
```

同时计算：

```text
d_state：
实际状态与预期执行状态的偏差

d_degradation：
保持当前分配时的任务性能退化预测

d_margin：
能力、时间、能量和通信约束裕度损失

d_uncertainty：
世界模型预测不确定性
```

## 三、事件触发机制

综合触发指标定义为：

\[
\Gamma_t =
w_1 d_{\text{state}}
+w_2 d_{\text{degradation}}
+w_3 d_{\text{margin}}
+w_4 d_{\text{uncertainty}}
\]

其中四个权重在训练场景上固定，开发场景不得重新调整。

事件触发规则：

```text
强事件：
无人机失效、关键任务新增、通信网络分裂
→ 直接触发

一般事件：
Γt ≥ τ 且距离上一次重构 ≥ Δmin
→ 触发

轻微变化：
Γt < τ
→ 保持当前分配

最小触发间隔：
Δmin = 4分钟
```

阈值采用训练集校准：

- 只使用4个训练父场景；
- 按事件类型统计严重度分布；
- 取训练集非零严重度的预注册分位数作为初始阈值；
- 阈值写入 `THRESHOLD_MANIFEST.json`；
- 开发场景和测试运行只读取冻结阈值；
- 禁止根据开发结果重新调阈值。

每次检测必须记录：

```text
event_type
event_severity
gamma_value
threshold
triggered
cooldown_suppressed
strong_event
affected_scope
```

## 四、受影响区域识别

触发后构建影响子图。

受影响任务集合包括：

- 直接受到事件影响的任务；
- 预计延误或能量不足的任务；
- 与受影响任务存在前置关系的任务；
- 与受影响任务存在协同关系的任务。

受影响无人机集合包括：

- 当前执行受影响任务的无人机；
- 故障或能量不足的平台；
- 具备替代能力且在通信范围内的平台；
- 与受影响任务相邻的一跳平台节点。

重构范围判定：

```text
局部重构：
受影响任务 ≤ 6；
受影响无人机 ≤ 4；
通信子图保持连通；
不存在关键任务整体失效。

全局重构：
关键无人机失效；
通信网络分裂；
受影响任务超过局部上限；
局部约束修复无可行解；
多个事件同时发生且影响域重叠。
```

高层策略动作固定为：

```text
NOOP
LOCAL_REPAIR
GLOBAL_REPLAN
```

轻微扰动只能选择 `NOOP` 或 `LOCAL_REPAIR`；强事件允许直接进入 `GLOBAL_REPLAN`。

## 五、候选动作重构

候选生成器只使用公共信息和当前合法动作目录，每次触发最多生成16个候选：

1. `NOOP`；
2. 当前公开 C1 动作；
3. 最多7个局部任务转移、交换或插入动作；
4. 最多7个跨平台合法改派动作。

候选排序依据：

```text
公开任务优先级
任务截止时间裕度
平台能力匹配度
预计距离和能耗
通信可达性
任务切换代价
```

候选动作必须满足：

- 来自同一公共前缀；
- 来自同一快照；
- 使用同一事件 tape；
- 通过能力、库存、时间和通信约束；
- 具有稳定候选 key；
- 绑定完整环境动作；
- 候选之间不得重复。

候选数量不足16个时保留实际数量，禁止复制动作填充。

每个候选保存：

```text
candidate_key
full_environment_action
candidate_scope
public_prefix_hash
snapshot_hash
event_tape_id
legal
infeasibility_reason
```

## 六、世界模型

世界模型采用图编码器加时序预测器：

```text
图编码器：
编码 UAV—任务—环境—通信关系

时序模块：
GRU 或 Transformer 编码最近若干状态

预测头：
下一状态
任务完成进度
任务延迟
能量消耗
任务失败概率
通信风险
约束违反风险
```

世界模型输入：

```text
当前公共图状态
当前任务分配
候选完整动作
最近历史状态
```

世界模型输出：

```text
候选未来状态
候选全局效用
任务完成概率
能耗预测
延迟预测
风险预测
通信风险
约束违反概率
```

不确定性使用三个独立 seed 的世界模型预测方差：

\[
U(a)=\operatorname{Var}_{k=1,2,3}\left[\hat{y}_k(a)\right]
\]

世界模型作用：

1. 判断保持当前分配是否会导致性能退化；
2. 比较16个候选重构方案；
3. 向事件触发指标提供预测不确定性；
4. 向 G-WM auxiliary critic 提供候选后果特征。

世界模型在 PPO 阶段冻结，不能直接修改 actor logits。

## 七、分层强化学习

高层策略：

```text
选择 NOOP、局部重构或全局重构；
确定受影响任务集合；
确定参与重构的平台集合。
```

低层策略：

```text
在候选动作目录中选择具体分配方案；
执行任务转移、交换、插入、拆分和协同调整。
```

候选评价流程：

```text
高层策略确定重构范围
→ 生成最多16个合法候选
→ 世界模型预测候选后果
→ G 或 G-WM critic 评估候选
→ 低层策略选择候选
→ 约束修复
→ 输出任务分配
```

奖励函数：

\[
R =
r_{\text{completion}}
-r_{\text{delay}}
-r_{\text{energy}}
-r_{\text{risk}}
-r_{\text{communication}}
-r_{\text{switch}}
-r_{\text{reconstruction}}
\]

其中重构次数、重构规模和任务切换次数分别计罚，避免策略通过频繁重构获得短期收益。

## 八、对比方法

第一轮核心实验运行四组：

| 方法 | 触发 | 决策 |
|---|---|---|
| Periodic-G | 固定4分钟周期 | 普通图 GPPO |
| Event-G | 事件阈值 | 普通图 GPPO |
| Periodic-G-WM | 固定4分钟周期 | 世界模型辅助 critic |
| Event-G-WM | 事件阈值 | 世界模型辅助 critic |

核心比较：

```text
Event-G vs Periodic-G：
事件触发是否减少重构次数和通信量

Event-G-WM vs Event-G：
世界模型是否改善候选选择

Event-G-WM vs Periodic-G：
完整方法是否提高任务质量并降低重构开销
```

核心四组通过后，再加入论文中的扩展基线：

- 周期性全局重分配；
- 传统拍卖；
- 贪心动态重分配；
- 纯模型自由强化学习；
- 无事件触发的世界模型方法；
- 有事件触发但无世界模型的方法；
- 完整方法。

## 十、执行顺序

### M0：本地合同和实现检查

验证：

- 100×100地图合同；
- 6场景配置；
- 4 UAV + 2 helicopter；
- 12任务；
- 2×2扰动；
- 阈值校准不读取开发场景；
- 候选最多16个；
- 候选无重复；
- 影响域局部/全局判定；
- 约束修复；
- 世界模型冻结；
- G/G-WM梯度路径。

### M1：动态扰动与触发实验

只运行规则触发和周期触发，不训练 PPO，验证：

- 事件检测；
- 触发次数；
- 冷却机制；
- 受影响区域；
- 局部/全局选择；
- 触发延迟；
- 通信开销。

### M2：候选动作和真实后果采集

对每个训练窗口生成最多16个候选，运行同一事件 tape 下的配对分支，验证：

- 候选合法性；
- 后果差异；
- 任务延误；
- 能耗；
- 通信风险；
- 全局效用；
- 独立 NOOP 和非目标任务标签复算。

### M3：世界模型训练与恢复

使用4个训练父场景：

- seed 8201、8202、8203；
- 40 epochs；
- batch size 8；
- 保存三个 checkpoint；
- 新进程恢复；
- 验证预测一致性和不确定性输出。

### M4：四组 PPO

运行四组核心方法，保证：

- 相同初始 actor；
- 相同事件 tape；
- 相同开发场景；
- 相同候选目录；
- 相同 PPO 更新预算；
- 世界模型仅进入 G-WM critic；
- 世界模型参数保持冻结。

### M5：独立审核与结论

由 GPT-6.1 Sol High 只读审核：

- 事件触发是否真实发生；
- 是否减少不必要重构；
- 候选数量和后果差异；
- 世界模型是否真实训练和恢复；
- G-WM 是否真实使用世界模型；
- 约束修复是否有效；
- 四组比较是否公平；
- 是否存在未来信息泄漏；
- 资源账本和 checkpoint 是否可复算。

## 十一、通过和失败标准

通过条件：

- 所有场景为100×100；
- Event组重构次数低于Periodic组；
- 事件触发不读取未来信息；
- 每个触发点候选数不超过16；
- 至少80%的有效窗口有两个以上后果不同的合法候选；
- 局部和全局重构均能被触发；
- 世界模型预测误差和不确定性可计算；
- G-WM auxiliary critic 有有限非零梯度；
- 世界模型参数变化为零；
- 四组均完成真实 PPO 更新；
- checkpoint 可新进程恢复；
- Sol High 独立审核通过。

如果候选后果差异不足，停止训练，先修复场景或候选生成。如果 Event-G-WM 没有优于 Event-G，只能结论为“当前规模下未观察到世界模型增益”。如果 Event-G 能减少重构但任务效果下降，则需要调整触发指标或影响域识别，而不是直接扩大训练量。

本版本可以真实运行，但第一轮结论只覆盖三件事：

1. 事件触发是否减少不必要的重构；
2. 16候选动作是否提供足够的后果差异；
